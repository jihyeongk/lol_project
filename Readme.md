# 리그 오브 레전드 경기력 평가를 위한 설계 및 활용

## 1. 개요

리그오브 레전드(League of Legends, 이하 LoL)는 아시안게임 정식 종목으로 채택될 만큼 이미 그 인기와 파급력이 이미 증명된 게임이다. 
LoL을 플레이하는 가장 보편적인 방식은 랭크게임으로 5대5 솔로랭크 매치가 대표적이나 최근에는 칼바람 나락:아수라장 모드(소위 증바람 모드)가 나오면서 
5대5 솔로랭크 매치의 인기가 많이 줄어들었다. 그 이유로는 5대5 솔로랭크의 진입장벽이 높다는 문제와 초반 라인전 단계에서는 1대1이기 때문에
상대방이 대리나 부캐일 경우에 본인 티어에 비해 실력차이가 너무나 재미를 느끼지 못하고 상대방이 아닌 우리팀과의 불화로 인한 스트레스도 심하기 때문에
한라인에서 여러명이서 싸움을 하고 운이라는 요소로 한판 한판 재미를 느끼는 증바람 모드로 많이 몰리게 되었다.


그럼에도 불구하고 5대5 소환사의 협곡은 리그오브레전드 초창기 부터 있었던 증명된 맵이기도 하고, 대회에서도 5대5 소환사의 협곡으로만 진행하기 때문에
우리에게 더 익숙하고 수집된 데이터의 양이 많은 편이다. 또한 프로구간에서는 따로 현재 메타에 좋은 챔피언이나 상대 픽을 카운터치는 챔피언을 연구하는
데이터 분석가를 고용하는 경우도 있다. 새로운 패치가 이루어졌을때 가장 영향을 받는게 솔로랭크이기 때문에 솔로랭크는 대부분 메타를 가장 먼저 파악하고 있다. 
프로선수들도 솔로랭크로 현재 협곡의 메타를 파악하고 특정 챔프를 숙달하여 숙련도를 올리기도 하기 때문에 솔로랭크의 데이터는 중요하다.

요즘에는 생방송에서 실시간으로 양팀의 승률을 예측하는 경우도 있다. 대부분의 승리 요소는 양 팀의 골드 격차나 게임내의 오브젝트 요소와 같은것으로 이루어져 있지만,
그 안에는 플레이어 개개인의 슈퍼플레이나 유리한팀의 실수같은 요소는 나타낼수 없기 때문에 승률이 높다고 해서 무조건 유리한 팀이 이기지는 않는다.
솔로랭크 매치는 최대 2명의 소환사가 함께 플레이 할 수 있으며, 플레이의 일차적인 목적은 게임을 숙달하여 랭크를 올리는데 있다.
솔로랭크 매치는 최고 수준의 실력을 갖는 프로게이머나 스트리머도 플레이하는데,
일반적으로 실력을 유지하거나 새로운 전략 또는 챔피언을 테스트하는 목적을 가지고 있다[[1]](가능하면 참고문헌 URL을 찾아 이 사실을 뒷받침하는 링크를 제시).

따라서 이 보고서에서는 같은 포지션의 두 선수를 비교하여, 경기 중 어떤 요소가 소속 팀의 최종 승패를 예측하는 데 중요한지 분석하고자 한다. 골드 차이와 경험치 차이를 기본 피처로 사용하고, 누적 킬·데스·어시스트를 추가한 조건과 누적 데미지 차이를 추가한 조건에서 예측 성능이 각각 얼마나 달라지는지 비교한다. 이를 통해 포지션별로 성장 격차와 전투 기록이 갖는 추가적인 예측 정보를 살펴보고자 한다.

### 1.1 분석 데이터

LoL 개발사인 Riot Games는 자사의 개발자 웹페이지를 통해 데이터를 무료로 공급하고 있다. 데이터는 API(Application Programming Interface) 방식으로 
취득할 수 있는 이 연구의 분석 데이터는 2025년 1월 8일부터 2025년 4월 7일까지 한국 서버(KR) 챌린저 티어 300명이 플레이한 53,279건을 대상으로 한다.
여기서 챌린저 티어 300명은 2025년 4월 8일 기준이며, 합리적인 분석을 위해 20분 이상 진행된 54279건 중 20분이상 진행된 38075건을 대상으로 한다.

※ 위 경기 수와 기간은 기존 작성값이며, 전체 파일을 집계하여 확정한 값은 아니다. 전체 경기 수의 53,279건과 54,279건 표기는 확인이 필요하며, 표본에는 분석 기간 이후의 경기도 포함되어 있어 기간 필터를 적용해야 한다.

경기 결과는 `match_*.json`, 타임라인은 `timeline_*.json`에 여러 경기의 배열로 저장되어 있다. 두 자료는 `metadata.matchId`로 연결하고, 경기 내 선수는 `participantId`로 연결한다. 타임라인의 `info.frames`에는 약 1분 간격의 `participantFrames`와 `events`가 포함되어 있으며, 선수별 골드·경험치·레벨과 처치 이벤트를 확인할 수 있다.

### 1.2 경기력 평가를 위한 기본 방향
선행연구[[2]]()에 따르면, 동일한 데이터로 미드라이너에 대한 경기력 평가를 분단위 기준으로 실시했다. 이 연구에서는 선행연구를 바탕으로 
5개의 포지션(TOP, JUNGLE, MIDDLE, BOTTOM, UTILITY)에 대해 확장하여 라인별로 타임라인 기여도 지수(Timeline Contribution Index, 이하 TCI)를 설계하고자 한다.
여기서 BOTTOM은 원거리 딜러(ADC), UTILITY는 서포터(SPT)를 의미하며, 데이터의 `teamPosition` 값을 기준으로 구분한다.

라인별 TCI 모델링 방법은 지도학습을 기반으로 하여 입력을 해당 시점의 포지션별 피처, 타겟을 소속 팀의 최종 승패로 설정한다. 먼저 피처 조합에 따른 승패 예측 성능을 비교하고, 이후 TCI의 구체적인 산출·해석 방법을 정한다. 모델의 예측 확률을 개인의 인과적 승리 기여도로 해석하지 않는다.

$$
TCI_{LANE} (\vec{x}, t; \theta), ~~~where LANE \in \{ TOP,~JUNGLE,~MIDDLE,~BOTTOM,~UTILITY\}
$$

## 2. 변수 설정

### 2.1 타겟 변수 설정

본 연구는 같은 포지션의 두 선수를 비교할 때 **골드 차이와 경험치 차이가 소속 팀의 승패를 얼마나 잘 예측하는지**, 그리고 **누적 킬·데스·어시스트 또는 누적 데미지 차이를 각각 추가하면 예측 성능이 얼마나 개선되는지** 확인하는 데 목적이 있다. 이를 위해 타겟 변수는 성장 점수의 합이 아닌 **선수가 속한 팀의 최종 승패**로 설정한다.

경기 $m$의 선수 $i$에 대한 타겟은 다음과 같이 정의한다.

$$y_{m,i}=\begin{cases}1, & \text{선수 }i\text{의 소속 팀이 승리한 경우} \\ 0, & \text{선수 }i\text{의 소속 팀이 패배한 경우}\end{cases}$$

타겟은 매치 데이터의 해당 선수의 `win` 필드를 사용한다. 같은 경기에서 같은 팀의 선수들은 동일한 타겟을 가지며, 같은 포지션의 상대 팀 선수는 반대 타겟을 가진다. 경기 중 여러 시점을 관측하더라도 최종 승패 타겟은 동일하다.

골드 차이와 경험치 차이는 동일 경기·동일 시점에서 **본인 값 − 상대 포지션 선수의 값**으로 계산한다. 양수는 본인의 성장 우위, 음수는 상대의 성장 우위를 의미한다. 이 두 차이는 하나의 점수로 합하지 않고 별도 입력 피처로 사용하여 각각의 예측 정보와 함께 사용할 때의 효과를 비교한다.

입력에는 예측 시점까지 알 수 있는 기록만 사용하고, 최종 승패는 정답으로만 사용한다. 경기 종료 시점의 골드·경험치·누적 데미지나 최종 K/D/A를 과거 시점의 입력으로 사용하지 않는다. 예측 시점은 경기 종료 이전으로 제한한다.

본 분석에서 중요하다는 것은 해당 피처가 **평가 데이터의 승패 예측 성능에 도움을 준다**는 의미이다. 승패에는 다른 포지션의 플레이와 팀 전체 상황도 영향을 주므로, 예측 성능의 차이만으로 개인의 인과적 기여도나 승리·패배의 책임을 단정하지 않는다.

### 2.2 라인별 피처 설정

기본 조건은 **누적골드 차이와 누적경험치 차이**의 2개 피처로 구성하고, 확장 조건은 여기에 **누적 킬, 누적 데스, 누적 어시스트**를 추가한 5개 피처 조건과 **누적 데미지 차이**를 추가한 3개 피처 조건으로 나누어 구성한다. 두 확장 조건은 별도로 비교하며, 누적 데미지 차이 조건에는 K/D/A를 넣지 않는다. 현재 레벨은 자료에 유지하되, 이번 핵심 비교에서는 제외한다. 레벨을 추가하는 실험은 별도로 구분한다.

챔피언 정보는 사용하지 않으며, 각 선수와 상대 포지션 선수의 해당 시점까지의 관측값을 사용한다. 골드 차이와 경험치 차이는 본인에서 상대를 뺀 값으로, 양수는 본인의 우위, 음수는 상대의 우위를 의미한다. 누적 킬·데스·어시스트는 본인의 값을 사용하며, 상대와의 차이나 KDA 비율로 바꾸지 않는다.

| 피처 | 데이터 필드 또는 산출 방법 | 선정 이유                                                                       |
|---|---|---------------------------------------------------------------------------------|
| 골드 차이 | 본인의 `totalGold` − 상대 포지션 선수의 `totalGold` | 같은 시점의 상대 선수와 비교한 경제적 성장 우위를 나타낸다. 골드 우위는 아이템 구매 여력의 차이로 이어질 수 있다. |
| 경험치 차이 | 본인의 `xp` − 상대 포지션 선수의 `xp` | 같은 시점의 상대 선수와 비교한 경험치 성장 우위를 나타낸다. 경험치 우위는 레벨 상승과 궁극기 등 주요 스킬 습득 시점의 차이로 이어질 수 있다. |
| 누적 데미지 차이 | 본인의 `damageStats.totalDamageDoneToChampions` − 상대 포지션 선수의 동일 필드 | 해당 시점까지 적 챔피언에게 가한 누적 피해량의 차이를 나타낸다. |
| 누적 받은 피해량 차이 (TOP 전용) | 본인의 `damageStats.totalDamageTaken` − 상대 탑의 동일 필드 | 해당 시점까지 받은 누적 피해량의 차이를 나타낸다. 라인전에서 받은 압박이나 탱커·이니시에이터 역할의 정도를 간접적으로 반영한다. |
| 누적 킬 | 해당 시점까지의 `CHAMPION_KILL` 이벤트에서 `killerId`가 선수 ID인 횟수 | 상대를 처치한 횟수를 나타낸다. 누적 킬 횟수가 많을수록 누적 골드도 증가한다.    |
| 누적 데스 | 해당 시점까지의 `CHAMPION_KILL` 이벤트에서 `victimId`가 선수 ID인 횟수 | 사망으로 인한 성장·활동 기회 손실을 간접적으로 반영한다.                        |
| 누적 어시스트 | 해당 시점까지의 `CHAMPION_KILL` 이벤트에서 `assistingParticipantIds`에 선수 ID가 포함된 횟수 | 아군의 처치에 기여한 전투 참여 정도를 나타낸다.                                 |

킬·데스·어시스트는 최종 경기 결과의 값을 가져오지 않고, **예측 시점 이전 또는 해당 시점에 발생한 이벤트만 누적**하여 계산한다. 세 항목은 각각 별도의 피처로 사용하여 하나의 KDA 비율로 축약할 때 사라질 수 있는 정보를 보존한다.

누적 데미지는 **적 챔피언에게 가한 누적 피해량**으로 정의한다. 같은 프레임의 `participantFrames`에서 `damageStats.totalDamageDoneToChampions`를 읽고, 본인에서 상대 포지션 선수의 값을 뺀다. 이는 두 선수가 각각 모든 적 챔피언에게 가한 피해량의 차이이며, 두 선수가 서로에게 가한 피해량만을 뜻하지 않는다. 미니언·몬스터 등을 포함한 `totalDamageDone`은 사용하지 않고, 최종 매치 기록의 피해량을 과거 시점에 적용하지 않는다. 받은 피해량은 이 조건에 넣지 않고, 탑(TOP)에 한해 아래의 별도 조건으로 다룬다.

누적 받은 피해량은 **탑(TOP)에서만** 사용한다. 탑은 게임내에서 탱커나 이니시에이터가 나오는 경우가 많고 탱커가 나올 경우 누적 데미지량으로는 게임에서의 기여도를 측정하기 어렵기 때문에 받은 누적 데미지량도 추가한다. 같은 프레임의 `participantFrames`에서 `damageStats.totalDamageTaken`을 읽고, 본인에서 상대 탑의 값을 뺀다. 양수는 본인이 상대보다 피해를 더 많이 받았음을 의미한다. 물리·마법·고정 피해별 값(`physicalDamageTaken`, `magicDamageTaken`, `trueDamageTaken`)도 같은 위치에 있으나 이번 분석에서는 합계만 사용한다.

데이터에는 **챔피언에게 받은 피해만 따로 집계한 필드가 없다**. 타임라인의 `damageStats`와 매치 데이터 모두 받은 피해를 피해 유형별로만 제공하며, 피해를 준 대상(챔피언·미니언·몬스터·포탑)으로 구분하지 않는다. 따라서 `totalDamageTaken`에는 미니언과 포탑 등에게 받은 피해가 함께 포함된다. `CHAMPION_KILL` 이벤트의 `victimDamageReceived`에는 피해를 준 대상이 기록되지만 사망 직전의 피해만 남으므로 누적 피처로 사용하기 어렵다. 또한 상대 팀의 `totalDamageDoneToChampions` 합으로 팀 단위의 챔피언 피해는 계산할 수 있으나 선수별로 나눌 수 없다. 이러한 이유로 `totalDamageTaken`을 그대로 사용하고, 이 한계를 해석에 반영한다. 받은 피해가 많다는 것은 불리한 라인전을 의미할 수도 있고 앞에서 피해를 받아내는 역할을 수행했음을 의미할 수도 있으므로, 값의 방향만으로 경기력의 우열을 단정하지 않는다.

예비 확인으로 `match_0.json`·`timeline_0.json`의 20분 이상 30경기(탑 60명)에서 시점별 누적 받은 피해량을 집계한 결과는 다음과 같다. 이 표본은 14.24 패치 경기로 분석 기간 밖이므로 값의 규모를 가늠하는 용도로만 사용하며, 분석 기간 전체 경기에 대한 값은 `top_damage_taken_stats.py`로 다시 집계한다.

| 시점 | 평균 | 중앙값 | 표준편차 | 경기 수 | 선수 수 |
|---|---|---|---|---|---|
| 5분 | 2,040 | 1,924 | 706 | 30 | 60 |
| 10분 | 5,714 | 5,714 | 1,677 | 30 | 60 |
| 15분 | 10,812 | 10,987 | 2,629 | 30 | 60 |
| 20분 | 16,696 | 16,084 | 4,476 | 30 | 60 |
| 25분 | 24,713 | 23,838 | 6,374 | 19 | 38 |
| 30분 | 35,223 | 34,526 | 8,086 | 8 | 16 |
| 경기 종료 | 28,385 | 25,414 | 12,071 | 30 | 60 |

25분·30분은 그 전에 끝난 경기가 빠져 표본이 적고 긴 경기에 치우쳐 있다. 시간이 지날수록 분산이 커지므로 본인 − 상대의 차이로 사용하고, 여러 시간대를 한 모델에 넣을 때는 경과 시간을 함께 입력한다.

프레임의 `timestamp`는 정확한 60,000ms의 배수가 아닐 수 있으므로 경과 시간 구간을 기준으로 처리하고, 누적 킬·데스·어시스트는 선택한 프레임의 실제 시각까지 계산한다.

라인별 피처의 해석은 다음과 같다.

| 포지션 | 성장 관련 피처의 해석 | 킬·데스·어시스트의 해석                                                                                                                                                          |
|---|---|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 탑(TOP) | 상대 탑과의 골드 차이·경험치 차이로 성장 상태를 파악한다. | 킬과 데스로 처치 성과와 사망 부담을, 어시스트로 아군 처치에 대한 관여를 반영한다. 단, 킬을 모두 솔로킬로 해석하지 않는다. 누적 받은 피해량 차이로 라인전에서 받은 압박을 함께 살펴보되, 미니언·포탑 피해가 포함된 값임을 고려한다.                                                        |
| 정글(JUNGLE) | 상대 정글과의 골드 차이·경험치 차이로 자원 수급과 교전 등을 통해 형성된 성장 상태를 반영한다. | 킬과 어시스트로 처치 관여를, 데스로 활동 중단과 성장 손실 가능성을 반영한다. 킬·어시스트만으로 갱킹 성공 여부를 단정하지 않는다. 경험치 차이의 예측 정보는 골드 차이 및 K/D/A와 비교하여 확인한다. |
| 미드(MIDDLE) | 상대 미드와의 골드 차이·경험치 차이를 통해 성장 상태를 나타낸다. | 킬·어시스트로 교전 성과와 참여를, 데스로 사망 부담을 반영한다. 라인전과 로밍에서 발생한 성과는 별도 이벤트 분석 없이는 구분하지 않는다.                                          |
| 원딜(BOTTOM) | 상대 원딜과의 골드 차이로 경제적 성장 우위를 파악하고, 경험치 차이로 성장 상태를 보완한다. | 킬로 처치 성과를, 데스로 생존 및 성장 손실 가능성을, 어시스트로 아군 처치 관여를 반영한다. 골드 차이의 예측 정보는 경험치 차이 및 K/D/A와 비교하여 확인하며, 누적 데미지 차이를 추가한 조건도 별도로 비교한다.          |
| 서포터(UTILITY) | 상대 서포터와의 골드 차이·경험치 차이로 성장 상태를 해석한다. | 어시스트로 아군 처치에 대한 관여를 반영하고 킬·데스를 함께 고려한다. 데스만으로 부정적 기여를 단정하지 않으며, 아군 보호나 시야 기여는 별도 정보가 필요하다.                     |

위 설명은 피처 선정의 도메인 근거이며, 특정 피처의 중요도가 검증되었다는 의미는 아니다. 실제 중요도는 포지션별 성능 평가와 피처 제외 실험을 통해 확인한다.

기본 관측 단위는 **경기·선수·시점**이다. 같은 포지션끼리 모델을 구성하고, 다음 조건을 비교한다. 여러 시간대를 한 모델에 포함하면 모든 조건에 경과 시간을 공통 보조 변수로 추가한다.

| 조건 | 입력 피처                                                          | 비교 목적 |
|---|--------------------------------------------------------------------|---|
| A | 골드 차이                                                          | 골드 격차만으로 얻는 예측 성능 확인 |
| B | 경험치 차이                                                        | 경험치 격차만으로 얻는 예측 성능 확인 |
| C — 기본 조건 | 골드 차이 + 경험치 차이                                            | 두 성장 정보를 함께 사용할 때의 효과 확인 |
| D — K/D/A 추가 조건 | 골드 차이 + 경험치 차이 + 누적 킬·데스·어시스트                    | 성장 격차에 K/D/A를 추가한 효과 확인 |
| E — 데미지 추가 조건 | 골드 차이 + 경험치 차이 + 누적 데미지 차이                         | 성장 격차에 누적 데미지 차이를 추가한 효과 확인 |
| F — 받은 피해량 추가 조건 (TOP 전용) | 골드 차이 + 경험치 차이 + 누적 받은 피해량 차이 + 누적 데미지 차이 | 탑에서 성장 격차에 받은 피해량 차이를 추가한 효과 확인 |

핵심 비교는 **C 대비 D, C 대비 E의 성능 차이**이다. D와 E도 비교하여 K/D/A와 누적 데미지 차이 중 어떤 추가 정보가 승패 예측에 더 도움이 되는지 확인한다. A·B·C 비교를 통해 골드와 경험치를 각각 또는 함께 사용할 때의 차이도 확인한다. 골드·경험치 격차, K/D/A와 누적 데미지 차이는 서로 연관될 수 있으므로, 추가 효과가 작더라도 전투 기록이 게임에서 중요하지 않다는 의미로 해석하지 않는다. 이미 성장 격차에 반영된 정보와 중복될 수 있기 때문이다. 탑에서는 추가로 **C 대비 F**를 비교하여 받은 피해량 차이가 승패 예측에 주는 추가 정보를 확인한다.

## 3. 경기력 지표 모델링

---

### 3.1 모델 선정
최종 승패를 예측하는 이진 분류 모델을 선정하고, 작동 방식과 해당 입출력에 적합한 이유를 기술한다. 모델 종류는 아직 확정하지 않았으며, 각 모델 안에서 A~E 조건에 동일한 학습·평가 분할과 튜닝 절차를 적용하여 피처 조합의 효과를 비교한다.

같은 경기의 양 팀 선수와 모든 시간대 관측값은 반드시 동일한 데이터 분할에 포함한다. 전처리와 피처 표준화에 필요한 통계는 학습 데이터에서만 계산하고, 모델 및 설정 선택은 검증 데이터에서 수행한다. 최종 평가 데이터는 조건별 성능 비교에 사용한다.

### 3.2 모델링 결과
조건별 승패 예측 성능을 ROC-AUC, 로그 손실(Log loss), 정확도로 평가하고, 포지션·시간대별 결과를 제시한다. ROC-AUC와 정확도는 높을수록, 로그 손실은 낮을수록 좋다.

특히 같은 평가 경기와 관측 시점을 사용하여 C 대비 D와 C 대비 E의 ROC-AUC 증가량, 로그 손실 감소량, 정확도 차이를 각각 보고하고, D와 E의 성능도 비교한다. 경기 단위 재표집으로 성능 차이의 신뢰구간을 계산하여 우연한 변동 가능성도 확인한다. K/D/A 각각의 추가 효과는 필요시 C에 킬·데스·어시스트를 하나씩 추가하거나 D에서 하나씩 제외하는 후속 실험으로 확인한다. 실제 성능 수치는 실험 후 작성한다.

## 4. TCI 모델의 활용

포지션·시간대별로 골드 차이와 경험치 차이의 예측 정보를 비교하고, K/D/A 및 누적 데미지 차이를 각각 추가했을 때의 성능 차이를 경기 복기 및 분석 피처 선정에 활용한다. TCI의 구체적인 산출 방식은 실험 결과를 바탕으로 정하며, 모델 결과만으로 개인의 승리 기여도를 단정하지 않는다.
